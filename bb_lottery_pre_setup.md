# Lottery BP + PRE sweep on bivariate bicycle codes: setup and knob derivation

Sweep of the lottery BP decoder with the serial PRE phase over the BB code
family, generated by `zoo/study/gen_bb_lottery_pre_sweep.sh` and run by its
emitted `zoo/study/bb_lottery_pre_sweep.sbatch` (one SLURM array task per
point, one GPU each).

## Codes, rates, grid

| Code | d | n (= max_iter) | Hx / Hz alists (`examples/alist/`) |
|---|---|---|---|
| [[72,12,6]] | 6 | 72 | `bb_72_12_6.alist`, `bb_72_12_6_hz.alist` |
| [[144,12,12]] | 12 | 144 | `bb_144_12_12.alist`, `bb_144_12_12_hz.alist` |
| [[288,12,18]] | 18 | 288 | `bb_288_12_18.alist`, `bb_288_12_18_hz.alist` |
| [[360,12,24]] | 24 | 360 | `bb_360_12_24.alist`, `bb_360_12_24_hz.alist` |

Physical error rates: p = 0.0001, 0.0005, 0.001, 0.003, 0.005.
Grid = 4 codes x 5 rates = **20 points**. Only the d=12 alists ship with the
repo; the other three pairs must be added under the names above. Logical
check matrices are not needed (`logical_check_matrix: false` computes them
from Hx/Hz).

Error model: BSC at rate p, perfect syndrome measurement, check `lx`
(`check_type: hx`). This is the code-capacity path, not the stim DEM path
(the circuit-level variant exists separately for the surface code in
`surface_stim_4gpu.sbatch`).

## How fpi and pmi are derived

Notation: `fpi` = `flip_phase_iters` (lottery warm-up boundary),
`pmi` = `pre_max_iter` (PRE window length), `Λ` = `pre_max_lambda` = 16
(PRE pool size), `n` = iteration budget = `max_iter`.

Two empirical fits from the BB convergence-CDF study (`hard_phase`):

```
w(d, p)   = floor(2 + 4880 · d² · p²)      # peak-slope iteration (floor-2 fit)
cap(d, p) = floor(2520 · d^0.6 · p)        # 95%-tile convergence iteration
```

`w` is the iteration at which the first-convergence CDF rises fastest;
`cap` is the iteration by which 95% of converging shots have converged.

The lottery warm-up:

```
fpi = max( min(n − Λ·w, cap), w )
      │         │        │     └─ lottery must reach peak slope before PRE
      │         │        └─ never warm up past the 95%-tile iteration
      │         └─ leave room for Λ windows of the peak-slope length
```

(The surface sweep adds a 60/40 override at p = 0.005 for d = 15/21/27; it
never triggers for BB, where `w` stays well inside the budget.)

The PRE window length divides the remaining budget over the pool, with
**ceiling**:

```
pmi = max(1, ceil((n − fpi) / Λ))
```

Because the decoder schedules only complete windows,
`min(Λ, floor((n − fpi) / pmi))`, the ceiling can drop a few of the
lowest-ranked suspects when Λ does not divide (n − fpi) exactly; each
scheduled suspect gets a longer window in exchange.

Schedule per point: iterations 1..fpi run plain lottery BP; iterations
fpi+1..n run lottery BP plus the serial PRE phase (the ordinary lottery
sign-flip continues every iteration; no flip at iteration n).

## Decoder configuration per point

```yaml
decoding:
  algorithm: bp_lottery
  check_type: hx
  dtype: float32
  device:
    device_type: cuda
    device_idx: 0
  config:
    max_iter: <n>
    early_termination: true
    flip_phase_iters: [<fpi>]
    flip_mode: [lottery, pre]
    pre_max_lambda: 16
    pre_max_iter: <pmi>
    random_machine: sobol
```

Every knob not listed keeps its default: `cn_pick: rand_unsat`,
`vn_pick: max_unsat`, both tie-breaks true, all optimization groups on.

## Point folders and runner

The generator writes one folder per point under
`zoo/study/bb_lottery_pre_sweep/`, named
`bb_hx_d<d>_p<p>_fpi<fpi>_pml16_pmi<pmi>`, each holding the five yamls
(decoding, bsc error at rate p, matrix, perfect syndrome, lx check) plus
`points.txt` (one folder per line) and the array runner
`bb_lottery_pre_sweep.sbatch` with `--array` sized to the exact point count
(currently `0-19`). Each array task runs one point on one GPU:

```
syndrilla -r=<point> -d=<decoding> -e=<error> -c=<check> -s=<syndrome> \
          -m=<matrix> -bs=10000 -te=1000
```

Regenerate after editing the lists at the top of the generator
(`BB_DISTANCES`/`BB_NS`, `RATES`, `PRE_MAX_LAMBDA`, `BATCH_SIZE`,
`TARGET_ERRORS`):

```
bash zoo/study/gen_bb_lottery_pre_sweep.sh            # generate
bash zoo/study/gen_bb_lottery_pre_sweep.sh --submit   # generate + sbatch
```

`CODE=surface` at the top switches the generator to the rotated surface code
(surface formulas `w = floor(2 + 1400·d⁵·p³)`, `cap = floor(160·d^2.2·p)`,
n = d², including the 60/40 override and the `rotated_surface_<d>` alists).
